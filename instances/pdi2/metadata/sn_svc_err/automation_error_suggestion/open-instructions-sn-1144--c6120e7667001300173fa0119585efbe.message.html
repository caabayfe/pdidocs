Discovery cannot reach the target machine

Remediation Steps :

 

  1. Confirm port accessibility from the MID Server
    • Access the MID Server host directly (via SSH or RDP)
    • Use tools like telnet to verify that the target IP and the desired port can be reached from the MID Server host : telnet <target-ip> <port>. Note that Telnet is an application that operates using the TCP protocol. UDP connectivity cannot be tested using Telnet.
    • Ensure firewalls between the MID Server and the target allow traffic on the required port
    • If the machine isn't reachable, try connecting to it from a different MID Server.
    • See this for more details about the port probes

 

  1. Verify credentials are correct
    • In ServiceNow, navigate to Discovery → Credentials, and select the relevant credential
    • Use the Test Credential button to validate access— against the targeted IP and port 
    • If Test Credential flow fails, read this KB article: KB0657528  for detailed guidance on credential testing
    • To collect information about which credentials were attempted in the discovery process, set the mid.probe.collect_debug_info MID Server property to true and re-run discovery. The credentials details will be available in the corresponding ECC Queue record
