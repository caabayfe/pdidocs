Create a CI Lookup Rule

CI Lookup Rules define how asset data from third-party sources identifies configuration items (CIs) in your CMDB. When a imported vulnerability matches an existing CI in your CMDB, a vulnerable item (VI) is created. Well-written CI lookup rules help you accurately track your vulnerable assets and subsequently assign them for remediation. Role required: sn_vul.vulnerability.admin.

If you remove a lookup rule from this list, it cannot be recovered. As an alternative to deleting them, you can change and reapply the CI Lookup rules on this list. If you change a lookup rule, click Apply Changes on this page to rerun all rules on discovered items that match the updated rules.

  1. On this page, to create a new rule, click New.
  2. Review the following key terms and field descriptions to help you define how the rule identifies CIs in your CMDB.
    CI match in CMDB
    When a host ID from imported vulnerability data matches a CI in the CMDB using a lookup rule, it is populated in the Configuration item field on the vulnerable item record. The CI lookup rule used to find it is added to the Discovered Item record in the CI matching rule field.
    Unmatched CIs
    Records for any unmatched CIs are automatically created during integration imports and included in Discovered Items.
    Changes to CIs if you reapply lookup rules
    If a CI changes after you reapply rules, discovered items are updated with the new CI, and impacted detections and vulnerable items are also updated. The risk score, assignment rules, group rules, and remediation target rules are also reevaluated.
    Lookup method
    Choose the method the rules uses for matching. Script uses either a pre-built script (IP Address, DNS name, etc.), or, a custom script. For Script rules, implement the script following the comments included in the template of the default function. Field matching selects a table and field in the CMDB. For Field matching rules, specify the table and field to search within the CMDB. Fields must be a string or number.
    Source
    Available third-party vulnerability integrations for data imports.
    Source field
    Identifies the matching ID value found by third-party integrations on the asset, such as FQDN, IP, DNS, for example.
    Condition builder
    Set specific criteria for your matching rule with the condition builder.
  3. Fill in the fields.
  4. Click Submit.
  5. Alternatively, if you have modified rules, click Apply Changes to apply updates to existing discovered items.
