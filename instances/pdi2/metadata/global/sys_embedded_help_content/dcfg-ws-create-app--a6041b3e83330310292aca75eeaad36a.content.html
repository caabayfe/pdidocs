Application Model vs Application Service

If you will be creating a new DevOps Config application from an existing application model or service, here’s more info about the differences between the two.

An application model is a type of model that can be managed and tracked within a scrum development process. It is the reference object to which your application's configuration data will be tied.

An application service represents an instance of a business application or system in different types of development environments, like development, test, or production. It is the target environment to where your configuration data will be deployed, and is consequently linked to a deployable in your application.

Application services typically link back to an application model, where the intended state of configuration data for an application is defined.

Which to choose

If you already have a target environment, like Development or Test, that you know you want to configure and the application service for those environments have been defined, this option is the quickest way to get your configuration data defined and mapped to those environments. It’s the preferred option.

If there is no application service defined yet, but you have an application model already created (from other uses in the ServiceNow AI Platform), this is also the preferred option.
