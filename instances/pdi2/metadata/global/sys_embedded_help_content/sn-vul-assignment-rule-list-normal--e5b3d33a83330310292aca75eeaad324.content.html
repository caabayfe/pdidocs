Create a Vulnerability Assignment Rule

Vulnerability assignment rules define the criteria used to automatically assign vulnerable items (VIs) to users or user groups for remediation. Assignment rules are used to evaluate and assign a VI when a new VI is opened, that is, imported, created manually, or reopened. Unless you manually reapply assignment rules after the VI or its state changes, a VI is evaluated once. Role required: sn_vul.vulnerability.admin.

Set conditions so that the rule you create assigns vulnerable items automatically for remediation upon creation to a user or user group that you want.

  1. To create a new rule, click New.
  2. Review the following key terms and field descriptions to help you define how the rule assigns VIs for remediation.
    Execution order
    The default rule is the rule with the highest execution order value in this field. If there is no default rule, the VI remains unassigned when the vulnerability group rule makes the group assignment. A final rule that is a good catch-all is active=true.
    Assign using
    Choose one from the menu. User group: Choose this option to select any of the existing ServiceNow AI Platform user groups. User group field: Choose this option to select any assignment group field available using the cmdb_ci table. By default you see the following three group fields for Configuration Item: Approval Group, Assignment Group, Support Group. None indicates no default value for this field. Script: Choose this option to define conditions with a script in the panel.
    Condition builder
    Set specific criteria for your assignment rule with the condition builder.
  3. Fill in the fields.
  4. Click Submit.
  5. Alternatively, if you have modified assignment rules, click Apply Changes to rerun all changed rules on all active, open vulnerable items.
    VIs you have manually added are not updated.

Run high priority rules (items that need special handling, where risk is critical, or a VI should be handled by regulatory compliance) first. Next, run your general rules, where no special handling is required, and you know who should be responsible for them. Finally, create a default rule to assign VIs to the group that will figure out what assignment group it should belong to. This group could add another rule to cover their decisions. This default rule runs last.
