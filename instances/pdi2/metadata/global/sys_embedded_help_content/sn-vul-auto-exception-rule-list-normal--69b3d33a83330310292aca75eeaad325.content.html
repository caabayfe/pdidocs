Create an exception rule in Vulnerability Response

Exception rules automate the deferral process for vulnerable items (VIs). You might create rules to automatically defer VIs for a specified period if they can't be remediated or deferred immediately. Role required: sn_vul.vulnerability.admin.

After you create an exception rule, you submit it for approval. After it is approved, a remediation task (VUL) is created in a Deferred state by default. Starting from the Valid from date you entered for it, the exception rule runs on all the VIs that are created, in addition to any that are moved from the Closed to the Open states.

  1. To create a new rule, click New.
  2. Review the following key terms and field descriptions to help you define the rule.
    Execution order
    Enter a numeric value to determine the priority of the rule. If multiple rules can be applied to a VI, the rule with the lowest execution order value is evaluated first.
    Condition builder
    Set specific criteria for the vulnerable items you want the rule to apply to with the condition builder. An example might be, Vulnerability = CVE (#) and Risk Score is > 20.
    Execute on existing data
    If selected, the rule is applied against existing data when it runs for the first time.
  3. Fill in the fields.
  4. Save your edits or click Submit to request approval.
  5. Navigate to All > Vulnerability Response > Administration > Approval Rules.

You use the flow designer to approve exception requests for exception management, exception rules, and false positive management. If you are deploying Vulnerability Response (VR) for the first time, the flow designer is enabled by default. After approval, deferral rules support ordering, that is, the rule with the highest priority is run first. If a high-priority rule is applied on a VI, no subsequent rules are applied on it again, even if the condition matches the VI.
