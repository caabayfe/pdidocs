Create a Cloud Discovery schedule

Create schedules for discovering cloud resources based on the discovery method that you choose: service accounts or IP ranges. The discovery schedule defines the various settings for the cloud discovery.

Before you begin

  • Before you attempt to configure Cloud Discovery, you must have at least one validated MID Server with a status of Up. The MID Server must reach the IP ranges that you intend to discover. You can install the MID Server by using the guided setup or by manually downloading and running the installer.
    For more information on MID Server, see the following topics:
    • Use MID Server guided setup
    • Install a MID Server on Linux
    • Install a MID Server on Windows

    Ensure to configure the MID Server used for Cloud Discovery with the Cloud Management capability.

  • Ensure that suitable credentials are available in the ServiceNow AI Platform to connect with the service accounts on which you want to perform the discovery.
  • Ensure that Cloud Discovery has adequate permission to discover the resources of the target cloud.
    • For more ingotmation on Amazon Web Services (AWS) cloud permissions, see Control AWS access and permissions using policies.
    • For more information on Microsoft Azure cloud permissions, see Microsoft Azure Alert driven discovery.
    • For more information on Google Cloud Platform (GCP) discovery, see Configure the Google Stackdriver Logging service to auto-update the CMDB.

Role required: sn_cloud_ops_ws.cloud_ops_admin

About this task

The ServiceNow® Cloud Discovery wizard begins with the account selection and testing phase. To prevent long waits or unexpected timeouts, use the cdu.record.watcher.timeout system property to define the maximum waiting period for these Cloud Discovery configuration processes:
  • Service account validation
  • Member account discovery
  • Discovery of logical datacenters
The default timeout value is 300000 milliseconds or 5 minutes.

You can configure Cloud Discovery to auto-refresh the list of sub-accounts and datacenters before each scheduled discovery. For more information, see Enable auto-refreshing of sub-accounts and datacenters.

Procedure

  1. Navigate to Cloud Discovery > Dashboard.
  2. Select New discovery schedule.
  3. Select the cloud provider.
    1. Fill the values on the Choose the provider form.
      For description of the Choose the provider form fields, see Create a new discovery schedule form reference.
    2. Select Next.
  4. Select service account for the Cloud Discovery schedule or create a service account.
    For description of the service account form fields, see Cloud Discovery service account form reference. If you select an existing account, the system auto-completes the form with the available information.
    Note: VMware discovery can run without a service account. To discover VMware resources, configure the schedule to run on the IP address of the vCenter server.
    1. Optional: To check the connection with the service account, select Test account.
    2. Optional: If you're creating the discovery schedule for a management account, specify whether you want to discover all the member accounts or only specific member accounts.
      By default, all the existing member accounts are selected for the discovery schedule.
    3. Optional: If you're creating the discovery schedule for a management account and the validation process doesn't return the subaccounts, select Refresh or rerun the account validation.
    4. Select Next.
  5. Select datacenters for the discovery schedule.
    You can either select all the datacenters attached with the service account or select specific datacenters.
    1. Optional: If you want to discover specific datacenters, select the datacenters from the Select the data centers drop-down list.
    2. Optional: If the datacenters don't appear, select Refresh Datacenters or rerun the account validation.
    3. Select Next.
  6. Optional: Specify whether you want to discover the Virtual Machines (VM) and their attributes.
    1. Optional: Specify whether you want to perform VM discovery using AWS Systems Manager.
      Note: This option displays only when the system property glide.discovery.enable_ssm is enabled and AWS is selected as the cloud provider in Step 3.
    2. Select a MID Server or MID cluster that can discover the VMs.
      If you're not sure about the MID selection, select Auto-Select MID Server.
    3. Select Next.
  7. Create a schedule to execute the Cloud Discovery.
    1. Select an execution frequency for the Cloud Discovery schedule.
    2. Specify a start time for executing the discovery.
    3. Optional: Specify criteria to cancel the discovery.
    4. Activate the discovery schedule.
  8. Do any of the following actions.
