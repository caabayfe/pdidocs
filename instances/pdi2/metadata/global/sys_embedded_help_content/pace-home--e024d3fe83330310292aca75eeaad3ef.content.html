Policy as Code Engine (PaCE) Workspace

PaCE enables you to administrate the full life cycle of policies using PaCE in applications by searching, reviewing, and updating existing polices, and creating policies as required.

Policies

A PaCE policy is a set of pre-defined rules and logic that determines the desired behavior of an application or a service. When invoked, the rules in the policy are applied on the provided input, and a decision is reached. Document Type enables you to filter your policies by the type it was assigned to. Select the Policies tab to define and manage your PaCE policies.

Mappings

Static Mapping enables you to map a set of policies to a record or object such as an incident or deployable. Dynamic Mapping enables you to map a set of policies on a dynamic set of records or objects such as a set of incidents or a set of deployables. Document Type enables you to filter your mappings by the type it was assigned to. Select the Mappings tab to define the conditions to which the policy is to be mapped.

Variable Definition

Parameters can be passed to a PaCE policy to validate updates to an object (tables and document IDs). These variables apply to authoring in both low-code or JavaScript. Policy versions include three types of parameter inputs: API Variables, Config Parameters, and Record References. Select the variable tab you want to add to your policies.

Templates

Select the Templates tab to create PaCE templates for the PaCE policy forms that you use frequently.

Tags

Policy tags enable you to define a policy with relevant reference tags. These tags can be defined according to your requirements, providing an element of flexibility to your policy management.

Categories

Policy categories enable you to categorize your policies into relevant groups or sections.

Invocations

When a PaCE policy is invoked, the calling service passes the relevant object (tables and document IDs) that is being validated by providing the documentRecord object. PaCE determines which policies must be executed by using the mapping table and the documentRecord.

All selected policies are executed concurrently. When all the policies have been executed, a final single decision is returned (in JSON format) with information on all executed policies and policy-level decisions. The final decision can be:
  • complaint: Indicates that all the selected policies comply with the requirements and have returned a compliant decision.
  • non_compliant: Indicates that one or more of the selected policies do not comply with the requirements and have returned a non_compliant decision.
  • complaint-exception: Indicates that a policy exception has been approved and any policies that are non-compliant are set to the compliant-exception state.
