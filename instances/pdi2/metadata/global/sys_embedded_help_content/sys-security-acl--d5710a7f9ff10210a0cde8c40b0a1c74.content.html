Access Control Lists (ACL):

Access Control List (ACL) rules manage access to resources by requiring users to pass a set of requirements before they can interact with a resource. Access to the resource will be denied if the ACL is empty i.e., no conditions are defined.

Decision Type:

The Decision Type field of the ACL form defines the access decision the ACL will respond with if the conditions on the ACL form are met.

  • Allow Access:
    The ACL grants access to the resources if all conditions are met. No access decision is made if all of the conditions are not met. If no allow access type ACLs grant access, access to the resource is denied.

  • Deny Access:
    The ACL denies access to the resource unless all conditions are met. Even if all the conditions on an ACL with the decision type deny access are met, an ACL with decision type allow access must still pass conditions to grant access to a resource.

    Deny type ACLs always run before the allow type ACLs, and can block access to a resource even if an allow type  ACL would otherwise grant access.

Applies To: 

The Applies To field on ACL form controls the scope of both "Allow-If" and "Deny-Unless" ACLs. Applies To  is only supported for record type ACLs. An empty 'applies to' field on a record type ACL causes the ACL to apply to entire table.

Conditions:

All conditions need to be satisfied.

  1. Roles: Users must have at least one of the roles defined in the list to access the resource.
  2. Security Attribute: Define security attributes that need to be evaluated to true.
  3. Data Condition: Define data condition that need to be evaluated to true.
  4. Script: Define script that returns true or false to either allow or deny access to the resource.
