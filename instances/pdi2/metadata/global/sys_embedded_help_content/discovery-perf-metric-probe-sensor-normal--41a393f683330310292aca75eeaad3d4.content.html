Discovery form for probe and sensor performance metrics

The IRE processing time is already included in the sensor processing time, but is isolated in the form to provided more insight into the identification and reconciliation of pattern payloads

The Probe and Sensor Metrics (Individual) form provides these fields:
Build/version
Build on which the Discovery was run.
Discovery status
ID number of the Discovery status from which the metrics were collected.
Target IP address
IP address of the target for this Discovery.
ECC queue input
Identifies a particular ECC input record in the ECC queue table.
ECC queue topic *
Identifies the java class in the MID Server that executes the probe.
ECC queue name *
Identifies the probe/pattern evaluated for performance in this aggregation.
Probe *
Name of the probe used for this Discovery.
Probe processing time
Interaction time of the MID Server with the target, including construction of the payload that is sent back to the instance. The time is in milliseconds.
IRE processing time
Time required to process the pattern payload on the instance by the Identification and Reconciliation Engine (IRE). IRE time is useful because it shows the part of the sensor time used by the pattern. The time is in milliseconds.
Sensor processing time
Time it took the sensor to process the payload on the instance for a Discovery. The time is in milliseconds.
* Used to uniquely identify a probe/pattern and accompanying sensor when gathering metrics for a Discovery.
