Intelligent search

Use Natural Language Query (NLQ) search to construct a search string using everyday language. As you enter text, a dynamic list of relevant suggestions appears, with items matching single words or part phrases in the entered text, for example table names.

NLQ and Intelligent search

  • Select Search tips to view tips on constructing search strings. The tips include details on usage, examples for single- and multi-table search, advanced filtering, and relationships in Intelligent Search.
  • Select Search to run the query if the search string is a valid CMDB query. If the query is not yet valid, the Refine your query dialog box appears.

    • If the CMDB query contains more than a single table, then select View in Query Builder to continue editing the query on the Query Builder canvas.

    • Intelligent Search can't convert your search string into a valid CMDB query if there are any ambiguities with specified table names or relationship types. If the query is not valid, the Refine your query dialog box appears and you can select from suggested CI classes to parse your search string into a valid CMDB query. Suggested CI classes are based on phrases in your search string. Use the drop-down lists to select the CI classes that match your intended search and then select View search results to run the query.
    • If Intelligent Search is unable to convert your search string into a valid CMDB query, then a feedback form appears instead of query results.
  • Select Show me... in the search box to see sample searches. The samples are common or complex searches, such as searches that involve application services.
  • Select Show me... in the search box to see Your recent searches list to rerun a previous search.
  • Select Results Feedback to submit feedback on the search results for your CMDB Admin to review.

CI Role requirements

In addition to the roles required to access CMDB Workspace, the following CIs require the app_service_user_role:
  • Mapped application service
  • Application service
  • Application service group
  • Dynamic CI group
  • Tag based service
The following CIs require the service_viewer_role:
  • Business service
  • Technical service
  • Application service outage
