Validate a snapshot

A snapshot of an application's deployable must be validated against a predefined set of policies.

The validation for a snapshot results in one of the following status:
  • Passed: Snapshot passes all mapped policies
  • Failed: Snapshot fails against mapped policies
  • Execution error: A mapped policy failed to run to completion

Only snapshots that pass validation against all mapped policies (using static and dynamic mapping) are published. Only published snapshots can be exported, which means the release pipeline can access only the current published version of a snapshot.

Revalidating a published snapshot is not applicable

A snapshot is validated against a predefined set of policies before it’s published. However, these policies may change over time, and a published snapshot may not meet the new validation requirements. This can cause the snapshot to become invalid and corrupted. If you deploy this snapshot to production, it might affect the deployment processes. To avoid this issue, you must unpublish and revalidate any previously published snapshot. This way, you can ensure that the snapshot complies with the latest policies.
