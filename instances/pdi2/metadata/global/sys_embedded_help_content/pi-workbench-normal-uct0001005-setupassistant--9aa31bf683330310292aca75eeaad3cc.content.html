Predict Service use case setup

This interface helps guide you through setting up this use case and assists you in creating a data-driven rule for your incident process. Incoming incidents include a predicted value for the Service field, applied by default with an indicator. The value is automatically applied on the Incident form.

Keep in mind that models are trained on the Service value of existing incident records.

Here are some ways you can optimize your experience:

  • Maximize your use-case implementation success by ensuring your incident dataset contains at least the amount of records defined in the system property setting (default is 10,000 rows).
  • If your service desk is distributed, consider creating a different use case for each service desk.
  • Start with incident records that best represent your typical incident process to achieve the most valuable data-driven results. From there, add increasingly unique or complex scenarios from other data flows, for example, from external integrations.

Glossary

Use case:
A task that uses machine learning alongside existing business processes to drive the outcomes it describes. Each use case will have a machine learning model operating within it.

What to do next

In the next stage, if you are creating a new model, you will need to decide on the input fields with the best predictive power, conditions to filter, and which services to include or exclude for triggering predictions.

If you are using an auto trained model, you can directly go to tune the model for the relevant services.
