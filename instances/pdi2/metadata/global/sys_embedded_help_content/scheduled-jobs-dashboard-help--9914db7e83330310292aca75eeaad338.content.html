Scheduled Jobs Dashboard

Use the Scheduled Jobs Dashboard tab to understand key health metrics and gain insights about your instance’s scheduled jobs.

This application enables you to do these tasks:
  • Understand how your scheduled jobs are being processed
  • Identify performance issues
  • Troubleshoot job issues
  • View information about the active delegators, active jobs, relevant alerts, and the current states of the events
Use the Scheduled Jobs tab to view the details of the scheduled jobs at an instance level grouped by job classification.
  • Stuck Jobs: These are jobs that are pinned to a node that no longer exists. You can remediate them using the following actions:
    • Delete it which will remove the job from sys_trigger permanently
    • Recover the job which will clear the System ID field and allow it to run again based on its Next Action time
  • Permanent Error Jobs: The scheduled jobs which have a State of Permanent Error. You can take the following actions on the stuck jobs:
    • Delete it to remove the job from sys_trigger permanently
    • Recover these jobs which set the state back to Ready. It can again run based on its Next Action time.
  • Pending Jobs: Jobs that are queued to be executed.
  • Running Jobs: Jobs that are actively running.
  • Jobs Classification: Job classification is a mechanism that allows you to group similar types of jobs together o that you can perform impactful analysis. You can set up classification criteria in the Job Classification Rules table. Use job classification on this page, as a filter, to analyze performance at a deeper level.
    Note: The default classification is TriggerType.JobName. Job classification for some jobs are provided by default.
  • Total Execution Count: Total number of scheduled job executions on your instance over a period of time.
    Note: Default time period is the last 24 hours and you can view the data from the last 7 days. The data originates from the sys_scheduler_job_history table.
  • Average Lateness: Average lateness in milliseconds of all scheduled jobs processed on your instance over a period of time.
  • Scheduled Job Trends: Use this table to understand which job classifications may have performance issues.
    Note: Default time period is last 24 hours and you can view the data from the last 7 days. The data originates from the sys_scheduler_job_history table. The Priority column states the priority at which the jobs are processed. The lower the number, the higher is the priority. For example, priority of 10 is higher than 100.
Note: If you select either of Stuck Jobs or Permanent Error Jobs tiles, the list view of the jobs shows up. The Lateness column on both the lists states about how late the job is based on the time it was supposed to run.
