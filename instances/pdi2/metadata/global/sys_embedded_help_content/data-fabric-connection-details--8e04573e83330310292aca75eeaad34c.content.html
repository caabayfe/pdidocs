Managing connections

Update connection details, view data assets, and manage access controls in an established connection.

Zero copy connections are managed by the connection admin. Once the connection admin grants access to an established connection, a data steward can access the connection to view data assets and create data fabric tables.

Connection details

The connection admin can update an established connection on the Connection details tab. For example, if data lake security details are updated by a data source administrator, the connection admin can update the security certificate.

The connection admin can also perform the following actions from the options menu:

  • Access the Data Fabric Logs [df_log] table by selecting View connection logs.
  • Temporarily disable the connection by selecting Deactivate.
  • Enable a disabled connection by selecting Reactivate.
  • Delete the connection by selecting Delete. The connection admin must delete all the data fabric tables using the connection before deleting it.

After a updating connection, the connection admin can verify the connection to the data source by selecting Test connection.

Note: Only the connection admin can access Connection details tab.

Data assets

After getting access to a connection, a data steward can view the schema, tables, and columns from a data source on the Data assets tab. After selecting a source table, a data steward can perform the following actions:

  • View data fabric tables that are currently mapped to a source table on the Data Fabric tables subtab.
  • View source columns that are available for data mapping on the Columns subtab.
  • Start mapping external data to a data fabric table by selecting Create data fabric table.
Note: Both the connection admin and data steward can access the Data Assets tab.

Access control

The connection admin can grant access to an established connection by adding an existing data steward role to the connection on the Access Control tab. For example:

  1. An instance admin creates a custom role in an application and assigns it to the users who will manage data for the application.
  2. Next, the connection admin adds the custom role to an established connection.
  3. Once the custom role is added to the connection, it inherits the df_data_steward role, thereby granting data steward access to users with the custom role.
  4. Users with the custom data steward role become data stewards for the connection.

Each data steward can access the established connection, view external data assets, map data, and create data fabric tables.

Note: Only the connection admin can access the Access control tab.
