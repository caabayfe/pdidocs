Policy version page

A policy version contains the version metadata, a policy script, and variable input definitions that you can modify as required.

Details

This tab shows the details of the draft policy version including the date on which it was created, the version name and number, the policy version used to create this draft version, and the description, When you create a new policy, a draft version of the policy is automatically created. To start using this version, you must publish it and change the state to Current.

Note: Only draft policies can be edited. The Description field is the only field that can be edited in this tab. To edit a Current or Archived policy version, you must first create a copy of the version and then update it as required.

Policy Builder

This tab shows the policy script that defines the logic and the variables that need to be passed for the policy. Variables are of twothree types:
  • Caller inputsAPI Variables: This variable is passed to the policy when it is invoked. All policies have a predefined Caller inputAPI Variable called Snapshot ID which cannot be modified or deleted.
  • Mapping inputsConfig Parameters: Mapping inputsConfig Parameters, including any mandatory inputs, can be passed when mapping policies to an object (tables and document IDs). Click NewAdd to add a new mapping input variable. Enter the variable name, description, select the type from the drop down list, and optionally, specify a default value for the variable. If necessary, select the Mandatory check box to make this a mandatory variable.

  • Data Collectors: This variable functions by collecting input process data from an external data source to provide an output. The output can be used in the policy logic to make a decision. You can define and manage data collectors by creating, editing, updating, and activating them to your policy builder.

Test Playground

The Test Playground enables you to test updates to a PaCE policy at any time, without the need to test or evaluate them in a Production environment. Updates to a policy can be made on-the-fly, and tested in real-time in a test environment. Before you publish a policy version, you can run a test evaluation of the version to determine if it is compliant, non-compliant, or compliant-exception. Evaluating a policy enables you to test repeatedly and apply any required changes to the policy version, before moving it to a production environment.

Executions

You can review the execution activity of any policy at any time. Recorded execution activity includes the time taken to execute, decisions of compliance, execution types, and the outcome of the execution.
