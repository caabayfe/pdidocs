System Events Dashboard

The System Events Dashboard module provides key health metrics and insights regarding the status of system events processing.

This application enables you to do these tasks:
  • Understand how your system events are being process and moved through the event queues
  • Metric-based graphical representation of the activities in the event processing system
  • Information about event processing alerts
  • Graphical representation of the current scores regarding the events on the instance
System Event Monitoring has Scores and Details sections separately and can be accessed using the tabs on the screen. Within the Scores section, you can find the following:
  • System Event Processing system: View the following tiles:
    • Active Delegators: Indicates whether there is an event delegator enabled. It delegates events to queues that use the delegated event functionality. Number of delegators in green is positive.
      Note: An event delegator is the one who delegates events to the jobs. By default, there is only one delegator at an instance level, and it can't be modified by the user. The users have to reach support if an event delegator is down.
    • Active Processors: Number of active event processors in the event system. Number in red indicates that the processor needs to be configured.
      Note: If the number is in red, ensure to check if the sys trigger jobs are configured correctly for the queue.
    • Active Jobs: Number of jobs associated for a queue in the automated job scheduler and check the queue registry for manual scaling. Based on the configuration and checks, the processing jobs are created automatically.
      Note: This card shows up only if the Queue doesn't use the delegator/dedicated model and is backed by processing framework. If this card shows up, the Active Delegators and Active Processors cards don't show up. If no queue is selected, Active Delegators, Active Processors, and Active Jobs cards show up simultaneously.
    • Event Processing Alerts: number of event processing alerts in the last 5 hour. When you click on the tile, it displays the Events Alerts table and helps listing out all the corresponding alerts.
      Note: Admins need to ensure if the event is ideal for a default queue or create a custom queue based on it's behavior.
    • Event Jobs on Schedule: Scheduled jobs events that are on schedule.
    Note: The Active Delegators and Active Processors cards show up only if the Queue uses the delegator/dedicated model. If these cards show up, the Active Jobs card doesn't show up. If no queue is selected, Active Delegators, Active Processors, and Active Jobs cards show up simultaneously.
  • Current Scores: Use this section to have a check on the sys_event table. The current scores card shows the current status of the events.
  • Trends: Metric-based graphical understanding of the activities in the event processing system.
    Note: By default, the trends are set to 24 hours. You can set it up to 15 days.

Within the Details section, you can review the details of an alert on an instance level. Go to the Events Alert Configurations list by navigating All > System Policy > Events > Configure Alerts. By default, five alerts are provided along with the application. You can either update the filter conditions of an existing alert or configure a new alert.
