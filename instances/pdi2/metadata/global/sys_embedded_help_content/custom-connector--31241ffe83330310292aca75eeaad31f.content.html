Enable integration with a custom connector

Set up a custom third-party connector by providing details and mapping fields to enable integration on a third-party connector.

Before you begin

Role required: evt_mgmt_admin

Procedure

  1. .
  2. In the primary navigation, select the Integrations Launchpad icon ( ) from the left navigation panel.
  3. In the Browse Integrations tab, select the All integrations drop-down list and select Custom.
    Only custom connector tiles are displayed.
  4. Select a custom connector tile.
    If a pop-up menu opens, select the data to track from that connector and select Continue.
  5. Provide the details for the connector on the Provide details page.
    1. In the Connector name field, enter a unique meaningful integration name for the connector type.
    2. Optional: In the Description field, enter information to help identify this connector type.
    3. Optional: From the Assignment group drop-down list, select the record from the assignment groups table containing the assignment group of the connector.
    4. In the Source field, provide text used as a filter to recognize events and that are added to the URL that is created and select Next.

    The Source field is commonly used as a filter to recognize events and to enable you to recognize the source of events and alerts easily. Consider using the name of the vendor. In addition, it's also part of the URL that is created at the end of this procedure.

  6. Optional: Set tags to be added to events to help locate and identify connectors of this type.
    1. Next to the Tags field, select the plus sign.
    2. In the pop-up menu, enter a tag key and value.
    3. Select Add.
    4. Optional: Add more tags by repeating this process.
  7. Optional: Select Upload image to upload the logo to display in your connector tile.
    If no image is uploaded, the default custom connector logo () is displayed.
  8. Select how you want to connect events.
    1. Select Directly to the ITOM instance.
      Provide details to configure the connector so that you can send the events to the ITOM instance since the connector is collecting data through an ITOM instance.
    2. Select Via the MID server.
      The MID server processes the event message and then passes the event to the instance. You can either select or create a MID server. If you select a MID server, select it from the available MID servers that are connected to an events listener. If you create a MID server, then configure the MID Web Server extension and the MID web service Event Collector Context.
  9. Select Next.
  10. In the Map Fields page, map the fields in your JSON code sample to the ServiceNow fields.

    Mapping the JSON code sample fields to the ServiceNow fields enables the system to create events correctly on the incoming data.

    The page is divided into three columns. The left column contains the ServiceNow field names. The middle column displays your connector field names. The right column displays your JSON sample after you copied it there.

    1. Copy and paste the JSON code sample taken from your custom connector JSON payload into the right column.
      The Severity and Message Key fields are automatically filled in to save you time and effort. The Message key gives the correct identifier of the events so that the de-duplication works correctly and you don't get redundant alerts, for example.
    2. In your connector column, enter at least one severity value that maps to the severity values listed in the ServiceNow column under the Severity field.

      You can enter the severity value from the JSON code sample. To set a severity value, you must be familiar with the payload of your third-party connector and which types of severity the connector supports. The severity values of the received events must match the generated events in your system.

  11. Select Next and save.
  12. In the Set-up push connector screen, copy the auto-generated URL parameter value to the clipboard by selecting Copy to clipboard.

    The URL is generated by the code that depends on the ServiceNow instance and connector to receive events from the third-party connector. Copy the URL to the clipboard and paste it on your third-party connector console to create a webhook that enables it to send events to the ServiceNow instance.

  13. Optional: In the Other fields section, in your connector column, provide third-party event parameters that aren’t required but provide additional information on the event.
    1. In the Description field, enter a description or leave empty.
      The Description gives you a meaningful alert description.
    2. In the Metric name field, enter the Metric name or leave it empty.
      The Metric name field is an attribute identifier of a particular metric that enables you to associate events with the performance metrics or KPIs that triggered the alert.
    3. In the Node field, enter the Node or leave it empty.
      The Node value is used for CI binding.
    4. In the Event time field, enter the third-party event's creation time or leave it empty.
      If the event time isn’t mapped, the system uses the default event time.
    5. In the Event time settings field, select the time format and the event time zone.

      The Time format field is a GlideDateTime field in UTC or GMT format. The maximum length is: 40 characters. The event Time zone times are stored in Coordinated Universal Time (UTC) and appear globally based on the system time zone.

  14. Optional: Add a field.
    1. In the Other fields section, select Add field to add the Resource and Type.
      A Resource is a node resource that is relevant to the event resource. For example, Disk C, CPU-1, the name of a process or service. A Type is a metric type to which the event is related. For example, Disk or CPU, which is used to identify an event record from which alerts are created.
    2. In the ServiceNow column, select the field.
    3. From the drop-down, select Resource.
    4. In your connector column, select the field and select the resource value from the drop-down list.
    5. In the ServiceNow column, select the field.
    6. From the drop-down, select Type.
    7. In your connector column, select the field and select the type value from the drop-down list.
  15. Select Next.
  16. In the Set-up connector screen, in the URL parameter value field, select Copy to clipboard to copy the auto-generated URL parameter value to the clipboard.

    This automatically created URL enables you to create a webhook that enables your third-party connector to send events to the ServiceNow instance.

  17. Select Activate and then select OK in the confirmation pop-up window.
    The connector is activated and saved. You can view the connector details on the Details tab, and your field mappings on the Fields mapping tab.
  18. Optional: Select the Related events tab to view related events to verify that the process was successfully completed and events are flowing into the system.
  19. Optional: Select Add automation to add business context to these alerts, group them, escalate to incidents and notify your team.
    The source and assignment group is auto-populated in the alert automation.

Result

After the connector is activated, you can then push events via the webhook to your ServiceNow instance.
