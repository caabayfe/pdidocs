Analyze log lines that surround an anomaly

Review the log lines that surround an anomaly for clues about the state of faulting systems. Analyzing these logs helps you identify the root cause of a Log Analytics alert.

Before you begin

Role required: evt_mgmt_operator or evt_mgmt_admin

Procedure

  1. On the Surrounding logs tab, review the following information:
    • Time - The timestamp of the log line, in the format that the source uses.
    • Application service - The application service where the metric was found.
    • Component - The logical component of the application service that generated the event.
    • Message - The inner message of the raw log line.
    • Level - The type of event. For example: Critical, Warning.
    • Host - The host identifier from the log line.
    • Log message - The raw log message without the header.
    Logs that surround the anomaly are retained and available for 30 days after the creation of the alert. The system does not delete these logs when the global retention period of logs expires.
    Note: When the retention period expires, the surrounding logs are available only on the Surrounding logs tab.
  2. Optional: View a different timespan of the log lines using one of the following methods:
    • Update the time range relative to the alert to a predefined time range in the Select range list.
    • Specify a different Start time or End time using the time picker.
  3. Optional: View the anomalous log data graphically as a function of time by selecting Log viewer.
    For more information, see Viewing the logs for an alert on the Log viewer.
