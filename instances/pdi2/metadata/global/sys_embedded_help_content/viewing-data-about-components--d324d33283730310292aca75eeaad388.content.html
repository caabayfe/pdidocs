Viewing data about components

This data shows you information about your uploaded components that includes Stale, Abandoned, and vulnerable components that have high-risk combinations. If you've installed third-party vulnerability insight integrations, you can also see how to remediate vulnerabilities and how likely it is you can fix them.

This module enables you to view more details about your components and their associated vulnerabilities:
All Components
The list of Stale, Abandoned, and Vulnerable components in your total component count. These counts can help you identify components that require your attention. These subsets of components might not match your total component count, because not all of your components might fit into these categories.
Stale
A current component version that is more than two major versions behind the latest version and two years behind the latest version.
Abandoned
Components with the latest versions in the history of their packages that are more than two years old.
Vulnerable
Components that have at least one associated vulnerability with any severity.
High-risk combinations
These components might require your immediate attention. Deps.dev provides the packages intelligence for Stale and Abandoned components. If you've installed the Snyk Vulnerability Insights integration, you can see the fix information for a vulnerability on a component. Fixes might not be available for all components. If imported, high-risk combinations are comprised of stale and abandoned components with at least one severe (Critical or High) vulnerability that you can fix with updates, replacement, or other type of repair. Completely fixable means that a component has an available version that can fix it. The percentage of the total number of high-risk components that have fixable versions is noted.
Vulnerable Components with Fixability
Components with vulnerabilities of any severity and how likely it is that you can fix them. There are totals and breakdowns of the components with Critical, High, Medium, and Low vulnerabilities. If a component has more than one vulnerability, the most critical vulnerability takes precedence.
Components by license
Totals and breakdowns of your components by licenses.
Component List
A list with component details. The Common Vulnerabilities and Exposure (CVE) and Fixability columns show you components that have vulnerabilities and how likely it is that you can fix them.
  • Complete means there are fix versions for all the vulnerabilities associated with the current version of the component.
  • Partial means there is a fix version for at least one but not all of the vulnerabilities associated with the current version of the component.
