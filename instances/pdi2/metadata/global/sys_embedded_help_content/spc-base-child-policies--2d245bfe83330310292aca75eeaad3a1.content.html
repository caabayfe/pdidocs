Using base policies and child policies for custom insights

Insights require activated policies. You can use multiple policies for your custom insights. You can add a base policy and child policies to a custom insight to help you look for specific data about your assets.

  • The Active tab lists your activated insights.
  • The Inactive tab lists your saved and deactivated insights. To activate a record, select it from the Inactive or All lists and select Activate.
  • You might want to use more than one policy for an insight if you want to focus your results on more than one matching condition.
  • Each policy you add after the base policy is part of a hierarchy. Data is gathered in the order of the policies you add, and conditions are inherited in a parent-child relationship. You can select any policy as your base policy.

    For example, say you want to create a policy that looks for on-premise assets that have vulnerability assessment tools but have not been scanned.

If you add more than one policy for a custom insight:
  • Level 1 is the base. This policy queries an extensive sample size in (N), for example, all your assets in your Active Directory reported by the Active Directory service graph connector.
  • Level 2 evaluates the results of the first policy. This policy evaluates only a subset of (N). For example, from all the assets in your Active Directory, return only those assets with vulnerability assessment tools that are not scanned for vulnerabilities.
  • Level 3 evaluates the results of policies 1 and 2, and so on. For example, from all the assets in your Active Directory with vulnerability assessment tools that are not scanned for vulnerabilities, return only those missing endpoint protection agents.
  • Any policies that you use for custom insights must be activated prior to activating the custom insight.
  • Select New insight to create a record.
