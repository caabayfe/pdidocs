Use the NG Filter Widget to build encoded queries in your Service Now Angular applications.

Usage

The only required information to initialize the NG Filter Widget is the target table.

Options

Configure the filter widget by passing an object into the filter widget using the filter-config attribute.

Name type default description
encodedQuery string undefined A string which will be parsed, internally converted into a GlideQuery object, and displayed as the current filter comparisons. Note: if an encodedQuery string is passed into the filter, an encodedQuery string will be emitted on "snfilter:update_query" event
queryObj GlideQuery undefined A GlideQuery object which will be parsed and displayed as the current filter comparisons. Note: if a glide query object is passed into the filter, an updated GlideQuery object will be emitted on "snfilter:update_query" event
sets boolean true Allow multiple filter criteria to be created. Criteria are delimited by a ^NQ in the query string, and will be treated as a global or condition. If true, new criteria button will display. If false only the first criteria will be decoded and rendered in the filter
dotWalking boolean true Allows a filter comparison to traverse to a related table and filter on that table's fields
saveFilter boolean true Show the save filter button, which allows saving of the encoded query string to the sys_filter table
testFilter boolean false Show the test filter button, which shows the record count that matches the current conditions in the filter widget
loadFilter boolean true Enable or disable load filter modal
sortFilter boolean true Enable or disable sort filter modal
runFilter boolean true Show the run filter button. On click this button will create an encoded query and emit the correct query type. If false, the filter will build and emit queries automatically on every change
clearFilter boolean true Show the clear all button. On click will clear the filter and reset it to an empty state.
closeFilter boolean true Show the close filter button. On click will close the filter and remove filter widget from DOM.
watchConfig boolean false Live updates on config object passed into filter.
relatedListQueryConditions boolean false Enable Related List Query Conditions.
ouputType string "glide_query" What type of query filter widget emits when run. Options are "encoded_string" and "glide_query". Defaults to "glide_query"

Events

The following events that are used to interact with query

Event Handler Description
snfilter:initialize_query $scope.$on Include a query (either GlideQuery objects or encoded strings) as a parameter and the filter will initialize on the given query parameter
snfilter:update_query $scope.$emit Emits the updated query, formatted to match the type of query that was passed to it. If no query was initialized, an encoded query will be emitted
snfilter:update_table $scope.$on Update the filter table after initialization. Pass in an object with a table and tableLabel properties.
snfilter:update_order_by $scope.$on Update the filter sort by passing a sort Array
$scope.$emit('snfilter:filter_change'); $scope.$emit Any time there has been an update to the filters internal structure, the 'snfilter:filter_change' event is fired
