Error Framework Configuration

Configuration properties for the Error Framework source applications

Configuration Properties

enabled
Type: boolean
Enable or disable the Error Framework for this application. When set to false, error logging will be disabled.
Values: true | false
Default: true
logging
Type: string
Sets the logging level for EFLogger. Controls which log messages are written to system logs. Levels are hierarchical: "error" shows only errors, "warn" shows errors and warnings, "info" shows errors, warnings, and info, "debug" shows all messages.
Values: "error" | "warn" | "info" | "debug"
Default: "error"
cleanup.batchSize
Type: integer
Number of error records to process in each batch during inactive error cleanup operations. Larger batch sizes improve performance but may impact system resources.
Range: 1 - 50000
Default: 10000
cleanup.inactiveDays
Type: integer
Number of days without new error instances before an error is considered inactive. Inactive errors may be automatically closed or archived by cleanup jobs.
Range: 1 - 365
Default: 30
requiredOrigin
Type: string
Specifies which origin fields (error_source and/or error_instance) are required during error validation.
  • "source" - Only error_source is required (most common)
  • "both" - Both error_source and error_instance are required
  • "none" - Neither field is required (errors can be logged without origin context)
Values: "source" | "both" | "none"
Default: "source"
additionalUniqueFields
Type: array of strings
Array of additional sys_error fields to include in error deduplication logic. By default, errors are deduplicated based on error code and key. Adding fields to additionalUniqueFields allows for more granular deduplication.
Supported values:
- "error_source"
- "error_source_table"
Default: []
maxCallsPerTransaction
Type: integer
Maximum number of Error Framework API calls (addError, classify, refine) allowed within a single transaction. Once the limit is reached, a warning is logged and further calls are silently suppressed for the remainder of the transaction. This mirrors the behavior of the platform's gs.log rate limiter and protects the system from runaway error logging loops. Set to 0 to disable rate limiting (unlimited calls).
Range: 0 (unlimited) or any positive integer
Default: 100000
ℹ️ Default Configuration Only
This property is not controlled per application. It must be configured exclusively on the Default Error Framework configuration record and applies globally across all source applications within a transaction.
classification.categoryMaxDepth
Type: integer
Controls the maximum depth of the error category hierarchy used during classification. A value of 1 means only top-level categories are considered. Increase to allow deeper category matching.
Range: 1+
Default: 1
async
Type: object
Controls asynchronous processing behavior for this application via dedicated event queues.

async.actionExecution (boolean, default: true)
When true, action execution items are processed via the error.framework.action event queue for improved throughput and reliability. When false, actions fall back to the legacy async business rule path.

async.errorProcessing (boolean, default: false)
When true, addError() returns immediately with { queued: true } and defers all database operations to the error.framework.error event queue. Callers cannot reference the error sys_id immediately. Error validation and the disabled-check remain synchronous.
Note: Errors with context payloads exceeding 4000 characters automatically fall back to synchronous processing due to event queue parameter size limitations.
async.actionExecution values: true | false — Default: true
async.errorProcessing values: true | false — Default: false
⚠️ Important Notes
  • Configuration changes take effect immediately after saving
  • Invalid JSON will prevent the configuration from being loaded
  • Missing required properties will fall back to the default Error Framework config
  • The logging level does not affect execution table logs, only system logs

Example Configuration

{
    "enabled": true,
    "logging": "info",
    "cleanup": {
        "batchSize": 5000,
        "inactiveDays": 45
    },
    "requiredOrigin": "source",
    "additionalUniqueFields": ["error_source", "error_source_table"],
    "classification": {
        "categoryMaxDepth": 2
    },
    "async": {
        "actionExecution": true,
        "errorProcessing": false
    }
}
