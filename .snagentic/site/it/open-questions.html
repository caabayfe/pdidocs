    Major incident management

    Rejection has no server-side role check

    On Promoting and rejecting - configuration

    Security observation: only the UI conditions require a major incident manager. The form action checks canRejectMIC(), and so does the list action's visibility, but the client-callable function it calls, MIMListActionsUtil.rejectMIC, checks only itil or sn_incident_write. The workbench REST operation is open to anyone with workbench access , and its REJECT branch sets the state with no role or state check, while its PROMOTE branch does check the role. So any service desk user who calls these endpoints directly can reject a candidate. Platform team: add a major_incident_manager check on the server, or accept the risk explicitly.
