    1. Log and categorise an incident

    For: Service desk agentWhere: Service Operations Workspace, the classic incident formChecked against pdi2 on 2026-10-20 (mirror fcd5bcad66af)

    Where you work

    In the Service Operations Workspace, open Incidents. The lists are Assigned to you, Unassigned (the queue nobody has taken yet), Open, Resolved and All. E04 Press New to log an incident. E05

    The new-incident form has the sections Incident, Impact, Assignment, Notes, Related Records and Resolution. E06

    Classic form: the same lists are under Incident in the navigator (with Open - Unassigned for the queue); Create New opens an empty form.

    Log an incident while you talk to the caller

    Transcript (5 steps)
    1. Caller. Start with the caller. Search by name, and their location fills in. A VIP caller shows an icon and a red field.
    2. Channel and category. Record how they reached you, then the category. The subcategory list follows the category.
    3. Configuration item. Choose the configuration item that is affected. It can fill in the support team for you.
    4. Priority. Set impact and urgency. The priority fills in by itself.
    5. Save. Write a short description and save. The incident gets its number, and the caller receives an email.

    Download the video (MP4)

    1. Press New in the workspace's incident list (classic: Incident › Create New).

    2. In the Incident section E07, Caller: search by name. Location fills in from the caller. E03 If the caller is a VIP, a VIP icon appears and the field turns red: treat them accordingly. E02

    3. Channel: how they reached you (Phone, Email, Walk-in, Chat, Self-service, Virtual Agent). E08 E09

    4. Category and Subcategory: what it's about. The subcategory list follows the category:

      CategorySubcategories
      Inquiry / HelpAntivirus, Email, Internal Application
      SoftwareEmail, Operating System
      HardwareCPU, Disk, Keyboard, Memory, Monitor, Mouse
      NetworkDHCP, DNS, IP Address, VPN, Wireless
      DatabaseDB2, Oracle, MS SQL Server
      Password Reset(none)

    5. In Impact, the Configuration item: the device, application or service affected. Choosing it can fill the support team for you (see Assign an incident and Choose the right configuration item).

    6. Impact and Urgency: see Set the priority. The Priority fills in by itself.

    7. Short description: one line a colleague understands without opening the incident, such as "VPN disconnects every 5 minutes from home". Caller and Short description are required. E01

    8. Description: the details: steps to reproduce, error messages, what has been tried.

    9. Save (classic: Submit). The incident gets its INC number, and the caller receives an email.

    If you can fix it on the call

    Assign it to yourself, write what you did in the resolution notes, and resolve it straight away (see Resolve an incident). This is still worth logging: it shows how often things happen.

    Copy an incident for another caller NEW

    Transcript (6 steps)
    1. Start. On the incident, open more actions and choose copy incident. Support agents see it on any incident, even a closed one.
    2. Caller. The dialog asks who the caller of the new incident is. You must fill it in.
    3. Attachments. If the incident has attachments, include attachments is shown and ticked. Untick it if the new caller should not get them.
    4. Copy. Choose copy. The new incident is saved straight away, with the description, category, configuration item, group and priority, and it opens.
    5. Link. Its only link back to the original is a work note saying which incident it was copied from. It is not a child incident.
    6. Check. The assignee, the state, the notes and the watch list are not copied. Check the new incident before you work on it.

    Download the video (MP4)

    Use Copy Incident when a second person reports the same kind of issue and you want a new incident of their own without typing it all again. If it is the same outage affecting many people, link them to one incident instead (see Escalate and link related work).

    The new incident links back only through a work note, "This Incident is copied from INC…". E14 It is not a child of the original. Check the description and the assignment group before you work on it: they are the original's.

    Who sees the action: anyone with the itil or sn_incident_write role, on an incident in any state, including closed ones. E10 It is switched on on pdi2. E12

    Tips

    • Search for open incidents with the same configuration item before you log a new one; it may be part of something bigger (see Escalate and link related work).
    • Write the short description for the next person, not for yourself.
