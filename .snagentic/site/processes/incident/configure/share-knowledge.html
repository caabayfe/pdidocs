    Knowledge from incidents - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)Operator guide: Create and link knowledge from an incident

    The applications NEW

    ScopeWhat it gives incident management
    sn_sow_incthe workspace actions Create Knowledge, Edit knowledge and Report Knowledge Gap, the related lists, the Agent Assist configuration for incident
    sn_km_centerKnowledge Center: the Create new article page that Create Knowledge opens
    globalKnowledge Management, the feedback task table, its ACLs and notifications, the close rule Incident Create Knowledge
    sn_guidancesthe attach actions on knowledge in Recommendations

    The mirror's plugin list shows KCS Integration for Incident Management (com.snc.incident.knowledge) inactive and Knowledge Management Advanced (com.snc.knowledge_advanced) active. The Now Assist for ITSM scope (sn_itsm_gen_ai) is not in the mirror. So every KCS and Now Assist branch below is off on pdi2.

    1. Create Knowledge NEW

    In execution order:

    1. Header. The layout Incident has a Create menu E07 built from the group Create, which lists two Create knowledge form actions and Edit knowledge. E06 One is the declarative action E03; the other is the UI action E04, which is inactive. E05 Q50

    2. Who and when. The declarative action requires itil or sn_incident_write E01 and canCreateKnowledgeArticle E08:

      Checkpdi2
      state in com.snc.incident.create_knowledge.multistate.enablethe property is not in the mirror, so the default 6,7: Resolved and Closed E08
      no article with Source task = the incidentone article per incident E08 E19
      KCS active → KBKnowledge.canCreatenot used: KCS is inactive
      submission workflow off → contributor right on glide.knowman.task_kbapplies: the workflow is off E10; the knowledge base is redacted in the mirror E09 Q10

    3. Interceptor. The action opens the route kb_interceptor with source/incident/source-id/<sys_id> E01 E02: Knowledge Center's Create new article page, interoperable in Service Operations Workspace. E12 E13

    4. Knowledge base and template. The KB Processor offers templates when Knowledge Advanced is active and the user can contribute to templates; the submission and KCS flows are off for incidents on pdi2. E14 E10 Versioning is on. E51

    5. Next. The page closes and opens a new record of the chosen template table, or kb_knowledge. E17 Its values come from the table map between incident and the target table, when a target is passed E15; the map Incident Standard Article is active, but its field maps are not in the mirror. E16 Q84

    6. The article starts in workflow state draft. E18 Publishing follows the knowledge base's workflow, outside incident management.

    Inactive: the UI action Create Knowledge would have built the article itself: Issue from the description and Resolution from the resolution notes, in glide.knowman.task_kb. E05 sn_sow_inc.enable_kb_template (false) is read only by that UI action. E11

    2. Edit knowledge NEW

    A server-script declarative action for itil or sn_incident_write E20 E21, shown when canEditKnowledgeArticle passes: Resolved or Closed, and exactly one article with the incident as Source task that the user can write. It redirects to kb_knowledge.do for that article and returns to the incident. E08 E20

    On the incident's articles related list, New (create-new-uxf) opens a blank article form when KCS is inactive. E22

    3. Report Knowledge Gap NEW

    1. Header. The workspace UI action is in the overflow menu of the layout Incident, order 600. E23 E24 Roles itil, sn_incident_write; condition: not Closed. E23 E25
    2. Dialog. Topic (mandatory, from the short description) and Description; Submit calls SOWIncidentUtilsAjax.createKnowledgeGap. E23
    3. Record. A kb_feedback_task (KFT…) with the topic, description, the incident as parent and the user as opener. E26 E32 The insert skips ACLs; the create ACL would also require itil or sn_incident_write. E26 E28

    The global UI action of the same name is the Agent Workspace version. E27

    Afterwards:
    Readthe assignee, the opener, anyone who can read the incident E29
    Writethe assignee, the opener, elevated users E30
    Elevatedknowledge admins; knowledge_manager, knowledge_domain_expert for tasks with a parent E31
    Turn into an articleCreate Article on the feedback task, for its assignee or an elevated user E36
    Notifynothing: KM Feedback Task: Created needs an article E33, and the reassignment rule skips tasks with a parent E34 E35 shared/Q06

    4. Knowledge at closure (classic form) NEW

    The business rule Incident Create Knowledge creates a draft article in glide.knowman.task_kb when an incident changes to Closed with Knowledge ticked, text from the additional comments. E37 The field defaults to false E38 and isn't on the workspace Resolution section E39, so it works only where the classic form shows it. Q32

    • Q50 Should the inactive Create Knowledge UI action and its form action be removed from the Create group? Decision, for the platform team
    • Q10 Which knowledge base should articles from incidents go to (glide.knowman.task_kb), and who may contribute to it? Decision, for the process owner
    • Q84 Is a new article from an incident filled in from it and given the incident as its source task, so that Edit knowledge appears? Check on screen, for the platform team
    • shared/Q06 Who owns the knowledge gaps reported from incidents, which have no assignee and send no email, and should an assignment rule or a notification be added for them? Decision, for the platform owner
    • Q32 Is the classic form's Knowledge tick box still wanted, now that the workspace has Create Knowledge? Decision, for the process owner
    • Q12 Should Agent Assist's Attach post the article to Additional comments, which the caller sees, or to the work notes? Decision, for the process owner
