    1. Dependency views NEW

    Three field actions on task, for the Service Operations Workspace view, each shown when its field has a value and with no required role: CI dependency view (cmdb_ci), Service dependency view (business_service), Service offering dependency view (service_offering). E01 E02 E03

    Each opens the route unifiedmap in the current workspace, rooted at the field's value, with the node class and five levels. E04 E05 E06 E07 The route E08 renders the CMDB Workspace's Unified Map page. E09 What the map shows is governed by CMDB read access, not by these actions. glide.bsm.max_levels (3) affects only the classic dependency view. E10

    2. Affected CIs and Impacted Services/CIs NEW

    The incident's workspace form lists task_ci and task_cmdb_ci_service near the top of its related lists, and task_outage and task_location further down. E11 The incident overview shows the same two lists, and the affected CIs that have an asset, as cards in its Impact section. E12

    Kept in step by business rules:

    RuleDoes
    Sync CI with Affected CIsadds cmdb_ci to Affected CIs and removes the previous one E29
    Sync BS with Impacted Servicesadds business_service to Impacted Services/CIs and removes the previous one E30

    Outages: Create outage, Add and Remove have no condition and no role. E35

    3. Refresh impacted services NEW

    Refresh impacted services on task_cmdb_ci_service, overview view, for itil and sn_incident_write E23; the classic form has Refresh Impacted Services in its context menu. E24 Both are shown only for the task classes in com.snc.task.refresh_impacted_services E25, an sn_cmdb_admin property whose value is redacted in the mirror. E26

    The refresh runs in TaskUtilsSNC: with com.snc.incident.refresh_impacted.include_affected_cis false on pdi2 E28, it deletes the rows not added by hand and inserts the services affected by the incident's CI, then tells the user it has finished. E25 E27

    5. Send Sms: a separate feature, off on pdi2 NEWsn_sow_itsm_common also puts Send Sms in the action bar of any task, incident included.

    E36 It is not part of dependency views: it sends a text message through Notify to people about the record. It is shown only when all of these hold E37 E38 E39:

    Conditionpdi2
    the user has notify_view or notify_adminnot known from the mirror
    glide.notify.task.phone_number set, or glide.enable.notify_on_task truenotify_on_task false E40; the phone number is redacted E41
    an active Notify number that can send SMSnumbers are data, not in the mirror; Notify for incident communication is off E42
    the user can write the incident and is conference leader

    With notify_on_task false and no sign of a Notify number, Send Sms is very likely hidden for every resolver on pdi2, which matches the SMS channel being off for communications (see Communicate). Enabling it needs a Notify provider and number: a decision for the process owner, not a configuration tweak.
