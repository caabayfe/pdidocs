    Working an incident - configuration

    Technical referenceReviewed 2026-10-17Checked against pdi2 on 2026-10-20 (mirror fcd5bcad66af)Operator guide: Work on an incident

    On hold

    Reason mandatory E01; comments mandatory for Awaiting Caller E02; reason cleared when leaving On Hold E03; caller reply resumes E04. When a linked problem changes state E05:

    • resolution code fix_applied: incidents On Hold - Awaiting Problem are resolved (Resolved by problem, the problem's fix notes as a work note);
    • resolution code risk_accepted: they only get a work note and the event incident.updated_by_problem; they stay on hold.

    No business rule or script action found acts on Awaiting Change or Awaiting Vendor.

    Hold reasons: 1 Awaiting Caller, 5 Awaiting Change, 3 Awaiting Problem, 4 Awaiting Vendor.

    Notifications while working

    Comments to the caller (see Who is told what), to the assignee and watch list E06, and the "state changed" notice when a caller's reply resumes the incident E07. Parent and child incidents share comments and work notes. E08

    Response SLAs start once a group is assigned and stop when the incident has an assignee and has left New; they never pause. Resolution SLAs stop only at Closed and pause on Awaiting Caller and Resolved. Q37 The eight priority SLAs are retroactive; the two OLAs and the underpinning contract aren't. E15 E16 E17 Their names point at groups and a CI the mirror can't name. Q54 Every definition takes its time zone from the caller's time zone. E13 E14

    The durations count only schedule time: Priority 3 resolution (1 day) is 24 hours of the 8-5 weekdays schedule, not one working day; the names understate the deadlines.

    Legacy escalation rules (sysrule_escalate, priority 1 to 4) also exist; whether the escalation engine runs isn't visible. Q60

    Attachments NEW

    Service Operations Workspace: the side panel route Attachments E20 opens the screen Attachment SNC for the record E21, which uses the attachments component E22. The census finds the older Agent Workspace action sn_itsm_workspace:Attachments, a contextual side panel action on incident with the same component tag. E23

    Access is the platform's sys_attachment ACLs, which follow the incident:

    OperationRuleRecord
    readcan read the incidentE24
    createcan write to the incidentE25

    The incident table has no no_attachment attribute, so attachments are allowed. E37 The client script (BP) Hide Attachment Link when Closed disables attachments on load of a Closed incident. E39 It is a form control, not an access rule: the create ACL only asks for write access to the incident. E25
