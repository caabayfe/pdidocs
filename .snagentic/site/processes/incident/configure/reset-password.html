    Service desk password reset - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror d13485ddb833)Operator guide: Reset a caller's password

    The applications NEW

    ScopeWhat it gives
    sn_sow_pwd_resetthe Reset Password buttons on incident and interaction, the owner checks, the route in the workspace, guided tours, the admin centre page
    sn_uib_pwd_resetthe Reset password pages (Identify, Verify, the verification checks, Reset, Success, Error) and their processors
    sn_pwdreset_ahthe reset, unlock and lock-state flows, and the confirmation email
    global (Password Reset plugin)processes, verifications, credential stores, roles, notifications, properties

    1. The button NEW

    Reset Password is a declarative action in the incident's action bar, for password_reset_service_desk, shown only when the incident is assigned to the current user. E01 E05 The same exists on interaction. E02 It sends the record's table and sys_id E03 to the route password-reset-main-snc, in a new tab titled Reset password. E04 E06

    When the tab loads, PwdResetUXFMainProcessor.canAccess asks the PwdResetUXFPreLoadValidation implementations for the record's owner; only the assignee gets in. E07 E08

    From an interaction, the processor inserts an incident (category password_reset) and links it to the interaction. It sets that incident's caller to the interaction's assigned_to, the agent, not the person locked out. E08 Check this before using it from interactions.

    2. The steps, by processor NEW

    PageProcessorDoes
    IdentifyPwdResetUXFIdentifyProcessorlists the user's service-desk processes (not public, reset or unlock; no soft PIN, no RPA store) and identifies the user E09 E10
    VerifyPwdResetUXFVerifyProcessorruns the process's verifications, with 3 attempts E11 E27
    ResetPwdResetUXFResetProcessorreads the process options, unlocks or resets through the credential store's flows E12 E22
    SuccessPwdResetUXFSuccessProcessorshows the generated password with a phonetic spelling E13

    After 3 failed attempts the user is blocked for 1440 minutes E27 E28; after a successful unlock, a new reset waits 1440 minutes. E29

    3. What is configured on pdi2 NEW

    ProcessActiveOffered to the service desk
    Service-Desk Password Reset for Local ServiceNowno E16it would be: not public
    Default Self Serviceyesno: public E19
    Employee Self-Service, Demo 1 and 2nono: public E20

    So no process can be chosen on the Identify page: the feature is installed but not usable. E10 E16

    If the service-desk process is activated as it stands, it E16 E17 E18 E21:

    • applies to every user, on the local ServiceNow credential store;
    • checks one thing: the agent asks for the user's email address and compares it;
    • generates the password, shows it to the agent, and emails it to the user ("Your new password", with the password in the body) E14 E15;
    • forces the user to change it at the next login, and can unlock the account.

    4. Roles NEW

    RoleGives
    password_reset_service_deskthe button and the tab E01 E23
    password_reset_credential_managercontains the service desk role E24
    password_reset_admincontains both, and SOW admin centre access E24 E25

    itil doesn't contain the service desk role E24: agents must be given it explicitly. The guided tours are shown to the same roles. E30

    5. Switching it on NEW

    The admin centre page Service Desk Assisted Password Reset lists what to review: processes, credential stores, verifications, process mapping, UXF routes mapping, password policies, session properties and agents. E26 For pdi2 that means at least:

    1. decide on the verifications: one email-address check is weak proof of identity E17;
    2. decide whether the password is emailed (send_email) or only read out (display_password) E16;
    3. activate the service-desk process;
    4. give the agents password_reset_service_desk.

    Not yet seen OPEN QUESTION

    1. Does the process owner want service-desk password resets on pdi2? Today it is off. E16
    2. Who holds password_reset_service_desk? Role grants are not in the mirror.
    3. Is the caller set to the agent on incidents created from an interaction a known product issue, or is a customisation expected? E08
    4. The Reset password tab was not opened on screen; with no active process, what does the Identify page show?
