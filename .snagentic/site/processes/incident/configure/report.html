    Reporting an incident - configuration

    Technical referenceReviewed 2026-10-17Checked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)User guide: Report an incident

    Entry points

    ChannelRecordBehaviour
    Portal and classic catalogCreate Incident producer E02Urgency and description mandatory; contact type self-service; title from the first 80 characters E01
    Service Portal tileGet Help E03Opens the Can We Help You? category
    Employee Centerdefault portal, suffix esc E04Get support menu; seen on screen, see Report an incident
    Classic New buttonNew E05Non-agents are sent to the producer
    Email, newCreate Incident E06Caller = sender, category inquiry, contact type email; see the security notes below
    Email, forwardedCreate Incident (Forwarded) E07As above
    Email, replyUpdate Incident (BP) E08Comment on the existing incident; "please reopen" reopens
    Other producersReport Outage E10, Report Performance Problem, Password ResetAsk a Question is inactive

    The caller is emailed when the incident is created. E09

    The cards of Employee Center's Get support window come from tables snagentic doesn't read, so what employees see was checked on screen. Which mailbox address receives incident email is instance configuration (email accounts), not mirrored. shared/Q18

    Email behaviours with security impact

    The inbound action Create Incident reads keywords and headers from any sender it accepts E06:

    InputEffectCheck
    a line assign: <user> in the bodysets Assigned to on the new incidentnone: any sender can choose the assignee E06
    email importance Highsets impact 1 and urgency 1, so priority 1 - Criticalnone: any sender can raise the highest priority E06 E11

    For replies, Update Incident (BP) applies assign: and priority: only when the sender has itil or sn_incident_write. E08 Consider the same check on the new-email action, or removing these lines, so that a P1 can't be raised and an agent can't be targeted by anyone with mail access.

    Open questions OPEN QUESTION

    • shared/Q18 Does the instance send and receive email (glide.email.smtp.active has no value in the mirror), and which address receives the emails that become incidents, so that it can be published to employees? Value not in the mirror, for the platform team
