    Closing and reopening - configuration

    Technical referenceReviewed 2026-10-17Checked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)User guide: Confirm the fix, or reopenOperator guide: Close, reopen or cancel an incident

    Permissions

    ActionAllowed whenRecord
    CloseResolved, and the user has itil_admin or is the callerE01 E02
    Close, accepted major incidentthe caller only if they have any role, or major_incident_manager (or itil_admin)E02
    Closed in the state listitil_admin onlyE03
    ReopenResolved, not an accepted major incident; itil, sn_incident_write, the caller or the openerE04 E02

    So resolvers with itil can resolve and reopen another caller's incident but not close it; that's deliberate in the platform. Q18

    Effects

    EventEffectRecord
    Reopenresolution fields cleared, reopen count +1E05 E06
    Closeinactive, closed by and atE09
    Closeopen incident tasks closed (if the property is on)E10
    Closecaller emailedE11
    Email "please reopen"resolved: reopened; closed: new incidentE12

    Auto close

    The auto close rule E07 closes resolved incidents not updated for glide.ui.autoclose.time days E08: 7. Only incident_manager can read or change the property. E08 The scheduled job that runs the rule isn't in the configuration snagentic reads, so how often it runs is still unknown.

    Create and delete (ACLs)

    OperationWhoRecord
    Createrole snc_internal (any internal user); an incident already in accepted major incident state only by major_incident_managerE15
    Createdenied unless the user is authenticatedE16
    Deleterole itil_admin only (admins override)E13
    Deletedenied unless the user is authenticatedE14

    Nobody with only itil can delete an incident: resolve it as Duplicate instead.

    Open questions OPEN QUESTION

    • Q18 Is it right that resolvers with itil can resolve and reopen another caller's incident but not close it? Decision, for the process owner
