    Technical referenceReviewed 2026-10-18Checked against pdi2 on 2026-10-20 (mirror d13485ddb833)Operator guide: Discuss an incident with colleagues

    The applications NEW

    ScopeWhat it gives incident management
    sn_oe_sfsSidebar itself: discussions (sys_cs_collab_chat, members, messages, the link to a record in sys_cs_collab_record), the header panel, ACLs, notifications, settings
    sn_sow_collabthe Service Operations Workspace Collaborate side panel and its Chat tab, participant suggestions, on-call resolution, older notifications (now off)
    sn_uib_collabthe base Collaborate panel for configurable workspaces, which sn_sow_collab extends

    The Collaborate Chat tab is not a second chat product: it reads the same Sidebar discussions linked to the record. E03 E10

    2. Who can start a discussion NEW

    • Workspace, Collaborate panel: shown on incident and change when Sidebar is supported E11; the + offers Start Sidebar discussion E10. The data brokers behind the panel run only for itil, sn_incident_write, interaction_agent and sn_change_write E12, plus sn_sow_collab.sn_collab_sow_admin for the section data E13. These roles contain sn_uib_collab.user, the role for the Collaborate panel. E14
    • Header Sidebar panel: no role in the mirror restricts it beyond hasAccessToCreateSidebar. E07
    • Next Experience form (classic UI in the unified navigation): the declarative action Open create collab chat modal on task puts an Open Sidebar discussion button in the action bar of saved records, for any user, when hasAccessToCreateSidebar passes and Next Experience is on. E16

    sn_sow_collab.sn_collab_sow_admin administers the SOW collaboration properties. E15 sn_oe_sfs.sidebar_report_viewer opens the Sidebar reports. E48

    3. Who can be invited NEW

    1. The candidate list checks access to the record. E17
    2. Requesters may be added: sn_sow_collab.enable_requester_in_sidebar_discussion is true E18, so the user query Exclude requester from sidebar discussion does nothing (it applies only when the property is false, and then removes users with no role but snc_internal). E19 hasPermission follows the same property. E03
    3. Suggestions: the caller and the assignee, and the first on-call user of the assignment group if on-call scheduling is active; only while the Participant Suggestions plugin is inactive. E21 The prefill with assignment group members is off. E20
    4. Groups: a group with on-call shifts resolves to its on-call users for incident, problem and change. E22
    5. Limits: sn_oe_sfs.com.glide.cs.collab.chat.candidate.limit 8 E23; the search and prefill limits (glide.collab.candidate_search_limit, glide.collab.group_search_limit, glide.collab.candidate_prefill_limit) have no value in the mirror.

    Open questions OPEN QUESTION

    1. For which tables is Sidebar enabled per record (isCollabChatEnabledForRecord)? The mirror doesn't hold that configuration; incident was seen working.
    2. Is the Participant Suggestions plugin (com.glide.sn_participant_suggestions) active? If so, the caller, assignee and on-call suggestions are replaced by its own.
    3. Is on-call scheduling (com.snc.on_call_rotation) active, with rotas for the incident groups?
    4. Should Sidebar Discussion Started and Sidebar Discussion Reminder (sn_sow_collab) be deactivated, now that nothing fires them?
    5. Should discussions be kept forever? The one-year cleaner is off.
    6. Is the 08:00 GMT digest time right for the callers' time zones?
