    Requests - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)Operator guide: Manage a request

    Headers

    The request header has Cancel Request E01; the item header has no close or cancel action. E02

    Server-side rules on the request

    RuleWhen, orderConditionEffect
    Cancel Flows Upon Cancellationafter insert and update, 100the state changes to Closed Incomplete (4)cancels the request's flows, "Due to request cancellation by …" E07
    Mark Request Closedbefore insert and update, 1200a closed request state or stageinactive, closed by and at, durations; state Closed Complete, Closed Skipped or otherwise Closed Incomplete E06
    Cascade Request Approval to Request Itemafter insert and update, 1300the request's approval changesits items get the same approval, rejection or cancellation E05

    So Cancel Request, which sets Closed Cancelled, ends as state Closed Incomplete through Mark Request Closed, and that state change cancels the flows. E06 E07

    Rejection notices

    When a request becomes Closed Rejected, two notifications fire on the same condition: the Request Rejected email E03, and the Now Mobile Request Rejected, which is a push notification only (no email, no subject). E04 Requesters get one email, plus a push message if they use the Now Mobile app. shared/Q09

    Catalog Tasks › New on a requested item NEW

    StepRecordWhat it does
    1. Showndeclarative action New (sn_sow_req) on the item's Catalog Tasks list E08 E09needs the item active and the right to create sc_task E08
    2. Whosc_task create ACL E10catalog_admin (and admin) only Q04
    3. Opensclient action Create new record E08a new catalog task with the list's query, so request_item is set
    4. Savedbusiness rules on insert E12parent and request filled, actual start set

    The flow Service Catalog item request creates its tasks with wait on, each step waiting for its own task. E11 Nothing in the mirror ties a hand-made task to the flow, so it neither blocks the next flow task nor the item's completion. Q18 Q09 Only cancellation reaches it: Close Tasks Due to Cancellations closes every task of the item. E12 E13

    • Q04 Should itil or sn_request_write be allowed to create catalog tasks, so fulfillers and agents can add one to an item without a catalog administrator? Decision, for the process owner

    • Q09 Should Service Catalog item request wait for every open catalog task of the item, hand-made ones included, before the item completes? Decision, for the process owner
    • Q05 Should service desk agents be able to copy requests, which today only admin and catalog_admin can? Decision, for the process owner
    • Q17 What does Copy carry over to the new request (items, variables, requested for), and does the copy start new approvals and flows? Check on screen, for the platform team
