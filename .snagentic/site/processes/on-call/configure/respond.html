    When on-call work reaches you - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror d13485ddb833)Operator guide: When on-call work reaches you

    The applications NEW

    All of it is in On-Call Scheduling (global): the trigger engine, the on-call subflows and their actions, the channel configurations, the reply rule and the escalation log. Trigger rules and the escalation policy that feed these flows are on Set the escalation and trigger rules - configuration.

    On pdi2 nothing runs: there are no trigger rules E01, no shifts, the Escalation Log is empty E02, and escalation logging is off. E26 E27

    1. The trigger NEW

    1. A trigger rule fires on the record. With the new trigger engine on, a subflow rule is run through On-Call: New Trigger Engine Handler. E03 E05 Only subflows are supported on this release. E04
    2. TriggerRuleSNC takes the group and user fields from the table's trigger rule configuration, or assignment_group and assigned_to, and the journal field, or work_notes. E06
    3. It stops if the assignee is already a member of the group. Otherwise it cancels on-call subflows already running on the record and starts the rule's subflow in the background. E06

    2. The flows NEW

    SubflowCategorySteps
    On-Call: AssignAuto AssignmentAssign and Notify SNC without notifying E07 E09
    On-Call: Assign and NotifyAuto AssignmentAssign and Notify SNC, SMS to the assignee E08 E09
    On-Call: Assign By AcknowledgementAssign By Acknowledgementone Per Rota subflow per shift, in parallel E11 E12, catch-all E13
    On-Call: Escalations by Emailemail onlyPer Rota by email E15 E16

    Every contact goes through On-Call: Send Notifications, which picks the email, SMS or voice subflow. E14 Shifts that overlap are all escalated. E32

    The SMS text. In On-Call: Assign and Notify SNC the Send SMS step's message reads "Hola, inc has been assigned 2 u." E10 It is sent as is to the assignee's SMS numbers whenever that flow runs. Replace it with a proper message, in a copy of the flow, before using Assign and Notify.

    3. Channels and answers NEW

    ChannelAcceptRejectSent by
    Email E20ACC in the replyREJOn-Call: Send Notification - Email
    SMS E21{message number}ACC{message number}REJOn-Call: Send Notification - SMS
    Voice E2212On-Call: Send Notification - Voice
    1. Email replies are read by the inbound action On-Call: Assign by Acknowledgement, for incident only. E23
    2. OnCallAssignByAckSNC checks the answer. Accept sets the assignee as system without running business rules, and writes "… acknowledged" to the work notes. Reject sends Resume per rota to the waiting subflow so that it moves on. E24
    3. Assigning the task by hand makes Resume On-Call workflows wake the waiting subflows, which then end. E25 Accepting doesn't run business rules, so it resumes them itself. E24

    4. The escalation log NEW

    1. The flows call the log actions at each start, level, attempt, contact and end. E09 E11
    2. OnCallEscalationUtilSNC writes them only when com.snc.on_call_rotation.log_escalations is true, which is the default. On pdi2 it is false, so nothing would be logged. E26 E27
    3. The Escalation Log module shows on_call_escalation to itil and rota_admin E28; the read ACL lets in sn_on_call_admin, readers of the record and members of the group. E29
    4. On the incident form, Assignment group carries the Track On-Call Escalation decoration, which appears only when escalation records exist. E30 E31

    Open questions OPEN QUESTION

    1. Escalation logging was switched off on pdi2. Was that intended? Do the flows still work as expected without escalation records, and should it be on before any trigger rule is created? E26 E27
    2. The SMS text of Assign and Notify is a placeholder. E10 Is it replaced at run time, or must the flow be copied and corrected?
    3. Is a telephony provider (Notify with a driver) set up for SMS, calls and conference calls? E18 E21 E22
    4. Should the reply rule cover problem, change and other tasks, not only incident? E23
    5. Accepting sets the assignee without running business rules E24: are assignment notifications and SLAs expected to react to it?
