    Your shifts, preferences and time off - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror d13485ddb833)Operator guide: Your shifts, preferences and time off

    The applications NEW

    Everything here is in On-Call Scheduling (global). Members need no extra role: the modules have none E01 E03, and the calendar pages need a calendar-read role such as itil (see See who is on call - configuration).

    1. My Schedule Report NEW

    The module opens a UI page whose processing script builds the report and redirects to the list v_user_rotation, filtered on the user. E01 E02

    1. It deletes the user's earlier report rows.
    2. For each of the user's groups, it collects the on-call spans in the chosen period with OnCallRotationPersonal.
    3. It keeps the user's spans, and adds the catch-all spans of active shifts where the user is the individual catch-all. E02

    2. Contact preferences NEW

    RecordHolds
    on_call_user_preferencea member's preference set, with its availability: an existing schedule or a custom one E04
    on_call_user_contact_preferencethe contact attempts: which device, in which order E05
    sys_on_call_contact_sourcewhere devices come from: the user's email, business phone and mobile phone E06

    The members' page is $oc_user_preferences.do, with the tabs Contact Attempts and Contact Overrides and an Availability picker. E03 E07 The page itself is not in the mirror.

    3. Reminders and subscriptions NEW

    1. OnCallRemindersNG sends the reminders ahead of each member's on-call time, as the roster's reminder settings say. E08
    2. It uses On-Call Reminder or On-Call Reminder Table. E09 E10 Time zones are not shown in reminders, and a roster can have at most 50 reminders. E11 E12
    3. A calendar subscription is a 10-character tiny URL with a personal API key, created when a calendar reader asks for it. E13 Subscriptions cover at most 364 days. E14

    4. Time off and cover NEW

    1. OCAddItem.timeOff records time off on the calendar. It refuses unless the user manages the group, or time off is accessible and the user is the member. E18

    2. Whether time off is accessible comes from the group's pto_approval_config, or from the property com.snc.on_call_rotation.pto.configuration when the group says Default. E16 E17

      SettingEffect
      Not allowedmembers can't add their own time off E17
      With approvalthe flow On-Call Time off approval runs E19 E20
      Without approvala proposed cover is mandatory; the proposal is Approval not required, coverage swaps automatically, and the approvers get Time off created for … E17 E18

    3. On pdi2: the property is not_allowed E15 and there are no group preferences E21, so only shift managers and administrators record time off.

    createOverride (cover for someone else's slot) has the same check. E18

    Open questions OPEN QUESTION

    1. Should members request their own time off? If so, set the property or each group's preference to With approval, and decide who approves. E15 E17
    2. The subscription link carries a personal API key: is that acceptable on pdi2, and how are keys revoked when someone leaves a group? E13
    3. $oc_user_preferences.do isn't in the mirror; which record defines it? E07
