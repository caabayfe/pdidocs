    3. Assess and find the root cause

    For: Problem coordinator, Problem task analystWhere: Service Operations Workspace, the classic incident formChecked against pdi2 on 2026-10-20 (mirror fcd5bcad66af)

    All of this happens on the classic problem form. A problem opened in the Service Operations Workspace by its address shows only Save, More actions › Create Outage, Delete and its related records E21; whether problems are to be worked there is not decided yet. Q01

    Assess

    Transcript (6 steps)
    1. Assess. In assess, check that it is a real problem. Does it recur? How many incidents? What impact?
    2. Confirm. Press confirm to start the root cause analysis.
    3. Record. Record what you learn in the cause notes, and the workaround as soon as you have one.
    4. Tasks. Split the work into problem tasks. Only problem task analysts can be assigned.
    5. Complete. Completing a root cause analysis task asks for the cause code, the cause notes, the proposed fix, and any workaround.
    6. Done. When the last task closes, the coordinator is emailed.

    Download the video (MP4)

    1. A new problem with an assignee is already in Assess; otherwise press Assess, and give the assignee if it asks. E01
    2. Check it is a real problem: does it recur, how many incidents, what impact? If it isn't one, see Accept the risk, cancel or reopen.
    3. Press Confirm. The problem moves to Root Cause Analysis. E02

    Take it yourself NEW

    To take a problem or a problem task without opening it, use the list.

    1. Open the classic Problems list (or the Problem Tasks list).
    2. Right-click the row and choose Assign to me. It works on one row at a time. E16 E17 Q11

    You are put in Assigned to and the record is saved. E16 A New problem then moves to Assess. E18

    • Who sees it: problem coordinators on problems, problem task analysts on problem tasks. E16 E17
    • When it is refused: "You do not have permission to update assigned to" if the record is closed or you can't change Assigned to; "Assigned to user … must be member of Assignment group …" if the record has a group you don't belong to. E16 E17
    • Unlike on incidents, it doesn't fill in a group for you: with no group, you are assigned with none. Set the Assignment group on the form if your team needs to see it. E16
    • You get no assigned to you email, because you made the change yourself. E19 E20

    Hand it over

    To give the problem to someone else, change Assignment group and Assigned to and save. Only problem coordinators can be chosen E09, and they must belong to the group: otherwise the save is refused with "Assigned to user … must be member of Assignment group …". E10 The new assignee gets "Problem … has been assigned to you"; with no assignee, the group gets "Problem … has been assigned to group …". E11 E12

    Find the cause

    Record what you learn in the Analysis Information section: Cause notes and, as soon as you have one, the Workaround. E03

    Split the work into tasks

    1. On the Problem Tasks related list, press New. E04
    2. Choose the type: Root Cause Analysis for the analysis itself, General for other work. E06
    3. In Assigned to, choose a problem task analyst: only they can be chosen. E05 To hand a task over, change its Assigned to the same way.

    The task moves Assess → Work in Progress → Closed with Assess, Start Work and Complete. Completing a root cause analysis asks for the Cause code, Cause notes, the proposed Fix notes and any Workaround. E07

    Cancel closes a task that is no longer needed, from Assess or Work in Progress, asking for the close notes. Re-Assess sends a task in progress back to Assess. E13 E14

    What happens next

    When the last task closes, the problem's assignee and work notes list get "… problem tasks are completed or canceled". E08 E15 Then share the workaround (Share a workaround and known error) and plan the fix (Fix and resolve).
