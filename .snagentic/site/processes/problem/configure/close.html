    Risk, cancel and reopen - configuration

    Technical referenceReviewed 2026-10-17Checked against pdi2 on 2026-10-20 (mirror fcd5bcad66af)Operator guide: Accept the risk, cancel or reopen

    Actions

    OrderActionConditionResult
    150Re-AnalyzecanReAnalyze E08Root Cause Analysis
    160Mark DuplicatecanMarkDuplicateOrCancel E08Closed, Duplicate
    180Cancel E10canMarkDuplicateOrCancel E08Closed, Canceled
    190Accept Risk E09canShowAcceptRisk E08Closed, Risk Accepted (the property moves it to Closed) E01

    Accepting the risk

    Goes straight to Closed. E01 Re-analyzing a canceled or risk-accepted problem needs the problem manager role E02 E03; closed problems are read-only. E04 The close fields are relabelled to match how it closed. E05

    Re-analyzing

    Update fields on Re-analyzing a Problem (before, order 110) runs when the state moves back to Root Cause Analysis: from Resolved or Closed it records the reopening and clears the resolution fields, so the problem can be resolved again. E07

    Duplicates

    Which records move to the original when a problem is marked a duplicate comes from problem.duplicate.records_to_move, readable only by problem managers, and its value was withheld from the records read. E06 Which related records move is not known yet. Q12

    Open questions OPEN QUESTION

    • Q12 Which related records does problem.duplicate.records_to_move move to the original when a problem is marked a duplicate? Value not in the mirror, for the platform team
