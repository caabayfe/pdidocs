    Resolving waiting incidents

    The script action Update Incident when Problem closes listens to problem.state_change and runs while the resolution code is Fix Applied or Risk Accepted. E01 E06 So it acts at Resolve (the state changes with Fix Applied set) and again at Complete, when no waiting incident is left. It touches only incidents On Hold - Awaiting Problem linked to the problem:

    Resolution codeEffect on those incidents
    Fix Appliedwork note with the fix notes; Resolved, close code Resolved by problem, notes "Related problem … closed."; assignee emailed E01 E02
    Risk Acceptedwork note "Problem team has accepted the risk of not fixing this problem …" only E01

    Communicate Fix sends the fix notes earlier, as a work note on linked incidents up to Resolved. E11

    Changes

    Changes are created from the form menu with the problem as parent. E05

    Closing

    Open tasks are canceled when the problem closes. E03 Whoever opened the problem gets Problem Closed. E09 Problem Closed inform Opener is a triggered notification that no record read sends E10: it duplicates Problem Closed if a flow ever does. The legacy rule SNC - ITIL - Update Related Incidents is active but can never fire. E04
