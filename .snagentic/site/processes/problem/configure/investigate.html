    Assessment and analysis - configuration

    Technical referenceReviewed 2026-10-17Checked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)Operator guide: Assess and find the root cause

    Transitions

    The model's transitions are enforced on save E02; New to Assess needs an assignee E01, and a New problem saved with one moves to Assess by itself. E03

    Problem tasks

    Task models are General and Root Cause Analysis. E04 Completing or canceling a task needs problem_task_analyst E05; a completed root cause analysis needs a cause code E06. No task can be created on a closed problem. E07

    Assign to me NEW

    Problem and problem task each have their own Assign to me with the action name task_assign_to_me, so they replace the one on task, which only checks canWrite(). E12 E13 E16 Both are list context menu actions (right-click on a row), not list choices, so they act on one record at a time.

    TableConditionRole record
    problem E12problem_coordinator when com.snc.best_practice.problem.madrid is active, else itilitil E14, which problem_coordinator contains E15
    problem_task E13problem_task_analyst when the Madrid plugin is active, else itilnone

    The Madrid problem best practice plugin is active on pdi2, so the coordinator and analyst roles apply.

    The script, the same on both tables E12 E13:

    1. Refuses an inactive record or one where assigned_to can't be written: "You do not have permission to update assigned to".
    2. Refuses a user who isn't a member of a set assignment_group: "Assigned to user {0} must be member of Assignment group {1}".
    3. Otherwise, if the record isn't already the user's, sets assigned_to and updates it. Unlike the incident action, it never fills assignment_group.

    It sets the field on the server, so the assigned_to reference qualifiers (problem coordinators, problem task analysts) don't apply; the conditions above do the same job. The update runs the problem's business rules, so a New problem moves to Assess. E03 Problem assigned to me and Problem Task assigned to me have send_self false, so the user who assigns themselves gets no email. E17 E18
