    No workspace list is on change_request or change_task. Changes reach agents through the category Tasks E01:

    The landing page's change lists have their own New (create-new-uxf, client action ba77e18f…) in the views sow_landing_page and sow_landing_page_assigned. E11 E12

    In the Tasks lists the more specific sn_sow_itsm_common action wins, so change tasks get no Assign to me there or on the form. E04 E07

    3. Creating changes and change tasks NEW

    1. Create Change Request on the incident E22 and on the problem E23 put change_link in the session; the after-insert rule Link change to incident in Wkspace writes the new change into the record's Change request (rfc). E21 These are workspace form-menu actions that open the sn_itsm_workspace record interceptor; on Service Operations Workspace the incident's menu doesn't show them (see Escalate and link related work). Q23
    2. Create Change Task is a form-menu action for itil and sn_change_write on saved changes. E24 E25 It opens the same interceptor, then the task with g_aw.openRecord. Q23
    3. The Agent Workspace New actions on Change Requests and Change Tasks related lists (with the parent filled in) don't apply, the workspace being off. E13 E14 E16

    4. Changing the type NEW

    Set State field on WS runs on a change of Type: it makes State read-only and rebuilds its choices from g_scratchpad.stateModel. E26 Its UI type is Mobile / Service Portal. Q24 The state model is only put on the form for changes without a model (chg_modelISEMPTY), so for changes with a model only the read-only part can apply. E27

    5. Agent Assist NEW

    1. The Agent assist SNC screen maps change_request and change_task to their configurations. E28

    2. Agent Assist [change_request] and [change_task] (global): active records only, no roles, source selector, 10 results, search on the short description. E29 E30 E31 The minimum search length is 3 (com.snc.contextual_search.min_length, see the incident configuration).

    3. Context Knowledge and IPC, shared by both: the searcher Default Sources and wildcard search off. E32 Its sources E33:

      OrderSourceRecords
      100knowledge, catalogknowledge articles, catalog items
      100Incidentsincidents of the last 6 months
      200Change Related Incidentscaused_byISEMPTY E34, plus a scripted filter on change_request only: active, created since work_start, else start_date E35 Q02
      300Open Changesactive, last 6 months E36
      400Closed ChangesClosed, closed in the last 6 months E37
      500Problemslast 6 months E38

    4. Actions: Attach (to comments, embedded link) E41, Flag Article, Helpful, Full View and Order, as for incidents; on change_request only, Link to Incident on Change Related Incidents. E39 Its REST operation link_chg_to_inc uses GlideRecordSecure, so the agent needs read on both records and write on the incident; it sets incident.caused_by and nothing else, although its dialog offers work notes and comments. E40

    6. Recommendations NEW

    The Recommendations tab needs itil or sn_change_write on changes and change tasks. E42 Both have an active context E43 E44 that searches through the ai_search engine E45, and glide.ais.enabled is false E46, so nothing is recommended.

    7. Sidebar discussions NEW

    For the base set-up (properties, ACLs, notifications), see Sidebar discussions - configuration. What is specific to changes:

    SettingChangesChange tasks
    Collaborate chat in the side panelcanLaunchChat allows change_request E47not allowed E47
    Data brokers of the Collaborate panelitil or sn_change_write E53same
    Open Sidebar discussion (Next Experience form, task)yes E52yes E52
    Participant suggestionsopened by, requested by, assigned to, on call E48none E48
    On-call group resolutionyes E49no E49
    Requester mapping (emails)none E50none E50

    Without a requester mapping getRequesterMappingField returns nothing, so neither the added to a discussion email nor the daily unread digest is sent for changes. E51 Add an inherited mapping (for example on change_request, field requested_by) if requesters should be told. Q03
