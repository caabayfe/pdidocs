    6. Schedule and implement

    For: Change requester, ImplementerWhere: Service Operations Workspace, the classic incident formChecked against pdi2 on 2026-10-20 (mirror d13485ddb833)

    Schedule

    Transcript (5 steps)
    1. Scheduled. Once approved, the change is scheduled for its window. Check it against the change schedules and the conflicts tab.
    2. Implement. At the start of the window, press implement.
    3. Tasks. The change gets two change tasks, implementation and post implementation, and waits for them.
    4. Close tasks. Each task goes from open to in progress to closed, with a close code and notes. Tasks can't be closed while the change is on hold.
    5. Record. Record the actual start and end in the schedule section.

    Download the video (MP4)

    When approved, the change is Scheduled for its planned window. Check the window against Change › Change Schedules and the Conflicts tab, which is refreshed when the dates or the CI change. E07 E08 Use Schedule if the change is waiting to be scheduled. E01

    Implement

    At the start of the window press Implement. E02 The change gets two change tasks, Implementation and Post Implementation; it waits for them. E03 Each task goes Open → In Progress → Closed and needs a close code and notes unless it is a planning task. E04 E06 Press Close Task when done; tasks can't be closed while the change is on hold. E05

    Actual start is filled in when the change moves to Implement, and Actual end when it moves to Review, unless you set them yourself first. E09 E10 Check them in the Schedule section if the work started or ended at another time.

    Tips

    • Press Implement when the work really starts: it stamps the actual start. E09
    • Take the change off hold before closing its tasks. E05
    • Look at the Conflicts tab again after moving the dates. E08
