    Creating and editing CIs in the CMDB Workspace - configuration

    Technical referenceReviewed 2026-10-19Checked against pdi2 on 2026-10-20 (mirror fcd5bcad66af)Operator guide: Create a configuration item

    The application NEW

    Creating and editing CIs in the CMDB Workspace belongs to sn_cmdb_ws. The three list actions on cmdb_ci are in the workspace's own action configuration E01 E02 E19 and apply to every class, as cmdb_ci actions do.

    1. Which button a list shows NEW

    ActionShown whenRolesOpens
    Create CIthe class qualifies for Manual Create CI E03 E08cmdb_manual_ci_ire_access or sn_cmdb_editor E03Manual Create CI E05 E06
    Newthe class doesn't qualify E04none; create access on the class E04the ordinary form, sysId -1 E07

    A class qualifies when it is in the configured class list and has an identification rule that doesn't rest on product_instance_id. E08 The list is all of cmdb_ci's hierarchy E09, less the classes the user can't both create and write, less cmdb_ci_service_auto and the classes in sn_cmdb_ws.manual_create_ci.global_class_exclusion (value redacted in the mirror). E08 E11 Q13

    So a user with itil but no CMDB role, who may create CIs through the cmdb_ci ACLs (see CI data and access), gets New only on classes without identification rules, and no button elsewhere. E03 E04 Who should create CIs is not decided yet. Q01

    2. Manual Create CI NEW

    1. The page is available to cmdb_manual_ci_ire_access, admin and sn_cmdb_editor E12; its data brokers run for sn_cmdb_editor and cmdb_manual_ci_ire_access. E13 E14
    2. Class, dependent-upon CI, identifier entries, and the additional attributes Operational status, Location, Managed by group, Owned by. E10
    3. Create runs IRE identification first; on a match the user is offered the existing CI. On no match the CI is inserted through IRE with the discovery source Manual via IRE; CI relationships go through IRE, person and group relationships are inserted directly; any implementation of sn_cmdb_ws.ManualCreateCIExtPoint for the workspace runs after. E08

    3. Bulk edit is hidden NEW

    The CMDB Workspace overrides the base Edit ({{count}}) E20 on cmdb_ci with a copy that requires the role nobody (sys_id b05940500a0a0aa70090a4893f6ff35d). E17 E18 This is the platform's way of hiding the bulk edit on CI lists, so changes go one CI at a time through the CI page. Q05

    4. Editing on the CI page NEW

    The CI page saves through CMDBWsExploreCIService.updateCI, which uses IRE when the class has identification rules and refuses a change that would make the CI a duplicate of another. E21 Its data broker runs only for sn_cmdb_editor E22: itil users can't save there, even though the classic form lets them edit CIs.

    Roles NEW

    RoleGives
    cmdb_manual_ci_ire_access (sn_cmdb_ws)Manual Create CI, in any workspace; nothing else E15
    sn_cmdb_editorcreate, read, update and delete of CMDB records, not policies; includes sn_cmdb_user E16
    sn_cmdb_adminincludes sn_cmdb_editor E16
