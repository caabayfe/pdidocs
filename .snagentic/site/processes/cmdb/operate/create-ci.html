    5. Create a configuration item

    For: CI owner, CMDB managerWhere: Service Operations Workspace, the classic incident formChecked against pdi2 on 2026-10-20 (mirror 9f3658cfb43d)

    Before you start NEW

    Create CIs in the CMDB Workspace with Create CI: it checks the CMDB first, so you don't add a second copy of a CI that already exists. E01 E07

    You haveYou see on a list of CIs
    sn_cmdb_editor (in sn_cmdb_admin) or cmdb_manual_ci_ire_accessCreate CI, for classes with identification rules E01 E12
    create rights on the class, no CMDB roleNew, only for classes without identification rules E02

    With the service desk role and no CMDB role, you see neither on most classes: ask the CMDB manager. E01 E02 Q01

    Create a CI NEW

    Transcript (7 steps)
    1. Start. On a list of configuration items in the CMDB workspace, choose create CI. You need the CMDB editor role, or the manual CI creation role.
    2. Class. Select the class of the new CI. Only classes with identification rules can be chosen.
    3. Identify. Fill the identifier entries, the values that tell this CI apart. Then the operational status, location, managed by group and owned by.
    4. Relate. Add relationships to other CIs, people or groups, so the new CI is not left an orphan.
    5. Create. Choose create. The CMDB is checked first; if nothing matches, the CI is created with its relationships.
    6. Duplicate. If a CI with the same identifying values exists, you are told it already exists and can review it. Nothing new is created.
    7. New. On classes without identification rules, the list shows new instead. It opens a plain form with no duplicate check, so search first.

    Download the video (MP4)

    1. Open a list of CIs in the CMDB Workspace and choose Create CI. E01 Q14
    2. Select the class for the new CI. Only classes with identification rules can be chosen; some special classes are created another way and aren't listed. E04 E05
    3. If the class depends on another CI (an application on a server, for example), pick the dependent-upon CI: the CI it runs on. If none exists yet, go back and create that one first. E04
    4. Fill the Identifier entries: the attributes that tell this CI apart from every other, and any the class makes mandatory. E04
    5. Fill the additional attributes: Operational status, Location, Managed by group and Owned by. E04 E06
    6. Add relationship(s), to other CIs, people or groups, so the CI isn't left an orphan. E04 E07
    7. Choose Create. E04

    What happens NEW

    • If a CI with the same identifying values already exists, you're told CI already exists and offered Review existing CI: nothing new is created. E04 E07
    • Otherwise the CI is created, with its relationships, and you can Review new CI, Create another CI or choose Done. E04 E07

    Classes without identification rules: New NEW

    On a class that has no identification rules, the list shows New instead. It opens an empty form, with no duplicate check: search for the CI first. E02 E03

    Change several CIs at once NEW

    CI lists in the CMDB Workspace have no bulk Edit: it is hidden on purpose, behind a role no user is given. E08 E09 Q15 Change CIs one at a time on their page, or ask the CMDB manager.

    Change one CI NEW

    Editing on a CI's page also goes through the identification engine. E10 If your change makes the CI look like another one, nothing is saved and you see Duplicate CI found; merge them, or correct the value. E10 Saving on the CI page needs sn_cmdb_editor. E11

    See Keep your configuration items right for what to keep up to date.

    Tips

    • Search for the CI before creating it, even with Create CI: a misspelt identifying value creates a second CI. E07
    • Fill Owned by and Managed by group: certification and routing depend on them. E06
