    E01 E02

    Each knowledge base has an owner and managers: they approve publishing and retiring where its flows ask for approval, can retire any of its articles, and edit the knowledge base itself. E09 E15 Who they are on pdi2 is not recorded here. Q24

    Where you work NEW

    The Knowledge Center opens on the Knowledge Hub, "Set up, manage, and monitor your knowledge bases". E03

    • Configurations: AI config, Guided setup, Knowledge management properties, User criteria diagnostics, Article optimization jobs and scans. E03
    • The Administration list group: Knowledge Bases, Article Templates, Style guides, Ratings, Search Log, View Log, Navigation Add-Ons, Messages and User Criteria. E04

    Ask for a new knowledge base NEW

    Transcript (5 steps)
    1. Ask. Anyone can ask for a knowledge base with the request knowledge base item in the service catalog, giving its name and the reason.
    2. Approve. One account fixed in the flow approves or rejects the request, and the requester is emailed either way.
    3. Created. Once approved, the knowledge base is created with the requester as its owner. The owner and managers get the knowledge manager role.
    4. Flows. Choose the publish and retire flows. Left empty, articles are published and retired at once, without approval.
    5. Access. Add who can read and who can contribute. On pdi2, a knowledge base without them is closed to readers. Check anyone's access with user criteria diagnostics.

    3. One user named in the flow, the platform's default admin account, approves or rejects it. E07 The knowledge_manager role's description expects knowledge administrators to approve them. E27 Q03
    4. Approved: the knowledge base is created with you as its owner, and you get Knowledge Base request approved. Rejected: "Your request for a new Knowledge Base has been rejected." E07 E08

    Create or change a knowledge base NEW

    Only knowledge administrators create knowledge bases; the owner and managers may change theirs. Knowledge bases can't be deleted: make one inactive instead. E09 Two knowledge bases can't share a title: "A knowledge base called '…' already exists". E10

    E17

    A knowledge base with no Can Read list is closed to readers, and one with no Can Contribute list is open only to its owner, managers and administrators: pdi2 blocks access where no user criteria are set. E20 E21 Q25

    Check someone's access NEW

    When someone can't see or edit an article, open User criteria diagnostics in the Knowledge Center. E03 Choose Knowledge Base or Article, pick it and the user, and choose Diagnose. E22 The answer says whether they can read or contribute, and why: for example "… has contribute access to knowledge base (…), because the user is the knowledge base owner, manager, or admin." or "User denied read access to the knowledge base because Can Read is not set." E21

    Knowledge managers and knowledge administrators can use it. E23 On the classic forms of a knowledge base or an article, the related link Run User Criteria Diagnostics does the same for admins, knowledge administrators and the knowledge base's owner and managers. E24 The Request Knowledge Base page, the diagnostics page and a knowledge base form were not opened on screen. Q36

    Tips

    • Ask for a knowledge base with the catalog item rather than by email: the requester becomes the owner, with the knowledge_manager role. E08 E11
    • Choose the flows when you create a knowledge base: an empty choice means instant publishing and retiring. E14
    • Use View Knowledge Base on the classic form to see a knowledge base as readers browse it. E28
